## Design acceptance walkthrough

- **S3 lifecycle:** encrypted input persistence, history, derived balances/buckets/goals/reports, mission evidence, private career state, retained AI output, queues/checkpoints/blobs/exports and backups; authorized runtime plaintext only. LLM transmission is minimized provider-runtime processing under its explicit contract. No mobile S3 cache in baseline.
- **Database-only compromise:** financial values/private content are ciphertext; PostgreSQL holds authenticated wrapped DEKs, never raw DEKs/KEKs. The classification table states intentional metadata/S2-exception exposure; no plaintext aggregate/index/financial digest is approved.
- **No circular hierarchy:** workload identity accesses external KEK/lifecycle metadata before user-data decrypt; these are not encrypted under the unavailable user DEK. Identity proof/authorization precedes unwrap.
- **Nonce/failure:** key-specific durable allocation is independent of business rollback; retries burn reservations. Allocator failure blocks encryption; restart/restore cannot reset it.
- **Rotation:** old/new wrapping enrollment handles partial dual-store failure; admitted writes drain before DEK switch; bounded CAS re-encryption preserves logical audit effects; retained backups prevent premature key destruction.
- **Restore/deletion:** payload/wrapped-key manifests, retained managed KEKs and authoritative external lifecycle/deletion state form the recovery chain. Restored sessions/writers are fenced; fresh DEKs precede new writes. No missing-key fallback or instant crypto-shred claim.
- **Mobile/AI:** device credentials have native secure storage; server DEKs never leave backend/key infrastructure. No-identity role contexts, provider restrictions, no action tools, strict outputs, timeout and late-result revocation are explicit.
- **PR-00 consistency:** deterministic server money, separate expectations/realizations, nonfinancial rewards, advisory AI, auditable history and approved stack remain intact. Privacy erasure is a distinct lifecycle rather than a normal history rewrite.
