# Planning goals and required income

Planning owns goals/expectations; [Finance](financial.md) owns actual money, [Work](work.md) owns declared capacity, [Identity](../identity.md) supplies the authenticated timezone. Goal target != balance; planned income != settled income; capacity != guaranteed income; projection != financial fact. AI never determines a rate. Goal operations create no Finance event, expectation, transfer or virtual progression.

## Goal rule 1 and funding

An owner-confirmed goal has bounded title/nullable description, positive targetMinor, supported currency, civil startDate/deadline (start ≤ deadline), and explicit retainedEarningsBasisPoints 0–10000. The retention assumption is the user-declared share of *additional gross earnings* available for this goal after costs/taxes/other uses; it is not a tax calculation or financial recommendation. No default assumes all gross income can be saved. Retention covers incremental costs on the additional earnings, not costs already represented by scheduled account outflows. This is a dedicated-account plan, not an assessment of all household obligations.

Funding is the entire balance of one explicitly selected owned active cash/savings account in the same currency. Existing settled balance supplies any starting allocation; no user-supplied starting money or sum of unrelated accounts. One account can be reserved by only one non-cancelled goal, including paused/completed goals; revising funding releases the prior account atomically. This is **exclusive Planning attribution**, not escrow: Finance can still spend/close the account. No partial allocations/contributions/transfers or FX. Current credited progress = max(authenticated settled balance,0); remaining = max(target − credited,0), preserving excess funds without capping the reported balance. Cancellation releases attribution and credits zero to the cancelled goal; it never changes money.

Lifecycle: create ACTIVE; ACTIVE → PAUSED or COMPLETED; PAUSED → ACTIVE; COMPLETED → ACTIVE (explicit reopening); any non-cancelled → CANCELLED; cancelled terminal. Completion is an explicit owner command, accepted only against active-account settled credited funds ≥ target in the same Finance snapshot. Store encrypted completion evidence/cursor; projection cannot complete. Completion records a historical achievement, not a permanent balance guarantee: later spending can show a current deficit while state remains COMPLETED until reopening. Completed goals retain exclusive attribution until cancelled/reopened/revised; only ACTIVE/PAUSED configuration can be revised. Expiry never changes status automatically. Safe business action and goal status are encrypted: completion can infer private financial success.

Every accepted command appends an immutable configuration/lifecycle snapshot and CAS-updates its current pointer/selectors. Server createdAt/recordedAt are separate from user-declared civil start/deadline; no backdated financial facts. Revision orders equal timestamps. Old revisions remain readable. Receipts bind `(owner,kind,random UUIDv4)` to normalized intent inside encryption; equal replay returns the original revision/calculation, different intent conflicts. Unknown commit outcome retries the same key, never invents a new command identity.

## Time and income formula 1

Calculation timestamp is server UTC. Convert it to a Gregorian civil date in the verified Identity timezone; date labels use that timezone, including DST, not UTC elapsed-hour duration. Effective planning start = max(today,startDate). Include start and deadline as whole civil planning days; today has one full declared planning day, **not measured remaining intraday work time**. Expired horizon has zero days; paused/completed/cancelled goals produce no actionable rates. Long deadlines are supported with constant-size calendar arithmetic; no days/30 approximation.

Let N be inclusive civil days, W eligible ISO Work weekdays with nonzero availableMinutesPerDay, H=W×availableMinutesPerDay (integer minutes). Month exposure M is the exact sum of intersected-month days / actual Gregorian days in that month; whole middle months contribute integers. No unavailable profile fabricates weekdays/minutes. Work's available time excludes its informational committed time.

For scenario balance B, goal deficit D remains target minus credited progress. Funding shortfall S=max(−B,0) also must be covered to fund the target; cancelled goals release attribution and have S=0. Required retained total R=D+S; additional gross total G=ceil(R×10000/retainedEarningsBasisPoints). R=0 gives G=0; positive R with retention=0 gives unknown G. Return D/S/R separately so an overdraft or projected outgoing shortfall cannot understate the additional earnings required. For ACTIVE, unexpired goals: calendar-day = ceil(G/N); normalized-week = ceil(7G/N); calendar-month = ceil(G/M); active-workday = ceil(G/W); available-hour = ceil(60G/H). Zero/unknown work denominators give null for workday/hour, with reason; calendar rates can still be known. All money uses Finance's minor strings/BigInt/bounds. Rates round **up** to the currency minor unit; rational numerators are not money values, and every published monetary result is range-checked. No floats/infinity, compounded interest or FX.

## Separate scenarios and declared capacity

CONSERVATIVE uses current settled credited funding only. PLANNED projects that same dedicated account using all pending user-confirmed predicted-income/receivable less scheduled-debit/payable whose due timestamp maps to a local civil date ≤ deadline, including overdue pending items. Full realization is an explicit mechanical assumption, never available cash. Sum categories separately, clip projected funding at zero, then calculate its own deficit/rates. At most 1,000 queried expectations; reject excess with BOUNDED_PERIOD_REQUIRED, never truncate. Pending items must pass existing Planning audit and Finance unsettled checks in the same snapshot. Closed funding accounts allow progress reads but require an explicit funding revision before a new calculation.

Work is observed before the locked financial snapshot through its application read. For a 1–366-day horizon, its existing capacity rule computes declared gross capacity using the same Gregorian civil labels; Planning labels the timezone projection explicitly and does not reinterpret it as UTC elapsed time. Longer goals still have exact time/required rates; horizon-wide Work capacity comparison is UNKNOWN beyond Work's approved bound. Return a fixed-monthly declaration separately when that is the sole model, so callers can compare it with the monthly required rate. Missing/zero availability is explicit. Currency mismatch leaves monetary comparison UNKNOWN; availability itself remains usable, with no conversion. Unknown variable/project amounts remain unknown. Project count is an explicit optional horizon assumption subject to Work validation.

Conservative arithmetic comparison of G versus known same-currency declared horizon capacity gives WITHIN_DECLARED_CAPACITY/ABOVE_DECLARED_CAPACITY; unknown/inactive/expired inputs give UNKNOWN. It is a mechanical gross-capacity comparison, not assurance or advice. Planned comparison is UNKNOWN when planned incoming amounts exist because they may overlap declared Work income; no capacity is added to projected cash. Work capacity is a shared declaration across goals, never an exclusive allocation of labor or guaranteed earnings.

## Explainability and boundaries

Each generation freezes only the required encrypted inputs: goal financial configuration/status/revision, server timestamp, Identity timezone/profile revision, minimized Work availability/currency/declared capacity and profile revision, Finance stream/checkpoint cursor/account revision/cursor/state/balance, and eligible expected-item IDs/revisions/kinds/dates/amounts. Freeze the effective local calculation date and each included dueLocalDate as interpreted at capture; replay never remaps historical UTC timestamps through a later timezone database. Inputs reproduce outputs under formulaVersion=1; no duplicate plaintext result archive, title/description/name/skills or identity data. Stored generations are immutable; later recalculation creates another generation and never rewrites previous evidence. A source cursor alone cannot reconstruct a historical pending projection, so the bounded minimized input snapshot is necessary.

Profile snapshots are explicitly pinned observations before Finance capture, not a claim of one cross-store simultaneous instant. Goal expectedRevision is checked again inside Finance's public snapshot; its user guard serializes goal revisions/allocations, postings and expectation transitions. Never nest Work/Identity reads while holding that guard. Planning owns all goal writes and obtains only Finance.snapshot/requireAccount/assertUnsettled reads. No foreign repositories, process-local locks, Finance receipts/stream updates or new crypto adapter.

Internal advisoryFacts returns only deterministic scenario deficits/rates/capacity comparison/time/currency and version refs; no identity or private goal text. It remains S3 and requires future AI purpose/consent/minimization gates before provider use. [Security](../security.md) owns classification: all goal content/status/actions/completion evidence/rates and calculation payloads are S3; timezone is S2 included only inside encrypted calculation inputs. S1 selectors: opaque owner/goal/account/calculation/command IDs, currency, revisions/generation/rule, timestamps, and reserved/released attribution (technical user-selected routing, not achievement). No amount/status text index or sensitive telemetry. [Persistence](../persistence.md) owns AAD/schema/erasure mapping.

Latest pointer must match latest authenticated history; missing/replayed selectors fail closed. Existing financial journal checks remain intact. Goals/calculations have no new independent freshness anchor: privileged deletion/replay of a complete valid suffix remains a documented residual risk. Include all snapshots/receipts/calculations and old key references in backup recovery/key migration/authorized erasure before deployment/retirement.
