# AI characters and privacy boundary

| Character | Purpose | Permitted context after deterministic processing |
| --- | --- | --- |
| 🤓 Alquimista | Explain reports/analysis | Selected-period aggregate ratios, coarse income/spend bands, trends, reserve/debt indicators, deterministic finding codes; no individual transactions |
| ⚔️ Estrategista | Recommend emergency/reserve missions | Reserve coverage band, shortfall/goal progress bands, safe effort constraints and approved mission catalogue IDs; no balances/creditors or raw evidence |
| 🔮 Oráculo | Suggest career/advancement | User-approved skill/role categories, coarse available-hours and capacity bands, broad advancement goals; no employer, exact salary/schedule or professional free text |

AI produces advisory content, never authoritative facts, calculations or mutations. [Financial authority](financial.md) and [Game adoption](game.md) govern validated action proposals. Numeric explanations display backend-calculated exact results separately from model prose; the model may describe approved bands/trends and cannot invent exact monetary figures. No financial/game command tools or raw-data retrieval tools are exposed to models.

## Context pipeline and payload schema

Authorize purpose/AI opt-in → decrypt necessary data temporarily → deterministic domain processing → minimize/quantize → remove direct identity/free text → construct validated allowlisted context → provider invocation → schema/content validation → authorized response/encrypted optional result. Release source plaintext/DEKs before waiting for inference. Derived context still has S3 inference risk; minimization is not a claim of anonymity.

Context schema version 1 has only `role`, `locale`, `context_schema`, non-identifying period duration, role-specific catalogue categories and named bands/ratios/trend/finding codes. No user/account/entity/job/session identifier, email, name, token, credential, bank identifier, IP/device identifier, precise dates/location, exact financial amount or complete raw history enters message content. Transport necessarily reveals backend/provider network metadata; disclose this residual separately. A provider request correlation ID is random per invocation, not a stable user ID; map it internally without exposing the owner to the provider.

Band/ratio schemas are explicit, bounded and deterministic, reviewed in PR-09 before activation. Suppress sparse/identifying combinations; never forward arbitrary strings because they fit a schema property. Locale and role/skill fields come from reviewed catalogues, not user notes. If an input cannot be minimized into the allowlist, omit it or mark insufficient context. No embeddings/vector store or external semantic retrieval is approved; [architecture](../architecture.md) owns dependency evidence gates.

## Provider and result contract

Only providers/endpoints with enforceable no-training, no prompt/output retention (including abuse/debug logs), approved subprocessors/regions/transfer terms and verified configured controls may receive context. A paid account or advertised privacy mode is not proof. If the chosen endpoint cannot satisfy this policy, AI stays unavailable; a policy exception needs an accepted ADR/legal review, not a silent fallback to another provider. Deterministic reports/financial operations remain available.

No server prompt/output/provider-body logging, request replay archives or persisted contexts. S3 results, evaluation excerpts and any useful retained response metadata follow [security](../security.md) encryption/retention; production data cannot become test/evaluation fixtures. Keep only safe operational event/latency/error fields outside those envelopes.

Use one provider invocation per interactive request with a maximum 15-second timeout and bounded input/output tokens specified in PR-09. No automatic retry that could create duplicated cost/retention without a new authorized request. Timeout, provider error, missing data, consent/session revocation or invalid output produces typed unavailable/insufficient-context status, never fabricated advice; discard late/revoked results. Server cancellation cannot guarantee a remote provider stopped processing already delivered context.

Outputs use strict role-specific schemas, approved recommendation/catalogue types and bounded text. Validate against supplied deterministic evidence; reject exact monetary claims, identity guesses, unsupported fact assertions, transaction instructions masquerading as execution, and active HTML/links outside approved presentation rules. Render as inert text. Never let a model response alter the context allowlist, role/permissions or rule versions.

Treat user notes, imported descriptions, retrieved text and model output as untrusted content. Baseline context excludes raw untrusted free text; prompts still separate fixed policy from bounded data. Prompt injection defenses combine restricted context, no action tools, validation and evaluations; a system prompt alone is not a security boundary. Suggestions require user adoption and deterministic owning-module validation. PR-09 must evaluate injection, leakage, unsupported numerics, sparse-context inference and provider failures before release; model/provider/output design is not permission to weaken this boundary.

## Alquimista rule 1 (PR-09.A)

Backend-only Reporting.alchemistFacts is not a provider DTO: exact monetary values/dates are quantized into a strict context {role:ALQUIMISTA,locale:pt-BR,context_schema:1,period:DAY|WEEK|MONTH|CUSTOM_SHORT|CUSTOM_MEDIUM|CUSTOM_LONG,findings:[catalogue codes],limitations:[catalogue codes]}. No arbitrary source string/identifier/currency/exact ratio/amount/date/free text passes. Initial product language is reviewed Portuguese, independent of Identity locale. Context requires realized activity and at least two nonzero independent evidence families among income, expenses, pending planning, goal; sparse/no-activity input returns insufficient context without invocation. Select at most six findings in stable priority order. Codes describe signs/trends, pending-versus-settled distinction, current goal funding, unavailable/stale required-income/Work context and partial-period limitation; no causal/financial-health inference. Explicit code/phrase ownership is the versioned AI model catalogue, tested against deterministic facts. Custom periods are ≤7 / ≤31 / longer civil days; no exact date/duration goes to the provider.

Output schema 1 contains a summary selection, bounded highlights/attention/observations, optional approved questions and mandatory limitation selections, each source-linked via catalogue IDs and DIRECT|EXPLAIN phrasing. Only currently evidenced findings in their allowed section are accepted; duplicates/unknown codes/free text/numeric fields/tools/HTML/Markdown are rejected. Backend renders reviewed plain text, not a made-up fallback. A model's selection/order/wording variant is the AI interpretation; all factual statements remain source-grounded. UI explicitly discloses constrained wording. Exact values remain in deterministic Crônicas. Changing catalogue, prompt, grounding/context rule or model configuration requires a new version and evaluations, never silently reuses an old result.

AI consent defaults disabled (revision 0). Explicit enable acknowledges forja.ai.v1 with provider/minimization/limitations disclosure; owner-CAS revisions and immutable policy acknowledgment history record grant/revoke. Core reports never depend on consent/provider availability. Disable prevents subsequent admissions, cancels locally tracked in-flight calls and marks live attempts cancelled; remote cancellation is best-effort and already-admitted data may have been delivered. Session/consent/source presence/key lifecycle recheck before output publication and reads; revoked/late output is discarded. Existing commentary is hidden while disabled; no automatic reanalysis on navigation, consent enable or report view.

Execution is a bounded synchronous call, not a durable job. Persist RUNNING admission before dispatch; SUCCEEDED/FAILED/CANCELLED are terminal, abandoned RUNNING becomes FAILED with unknown delivery, never re-dispatched. Recheck the admission deadline before dispatch too; an expired admission sends nothing. Cache key is owner + immutable Chronicle identity/generation + agent/prompt/configuration + consent revision; encrypted context fingerprint binds exact minimized input and source references. Request UUIDv4 binds intent; concurrent independent keys still share one active/successful execution for that binding. Successful viewing invokes no provider. Explicit retryOf current failed execution authorizes another attempt under quota; duplicate retry intent returns the same attempt. No automatic retry, autonomous loop or action tool.

Initial operational bounds: context ≤2 KiB, output contract ≤8 KiB, provider HTTP body ≤64 KiB, max_output_tokens=900, provider timeout 10 seconds (inside canonical 15-second interactive cap); at most one active call per owner, one dispatch/minute and ten per rolling 24 hours. Persist admitted attempt before counting cost; failed/unknown calls count. Limit changes require config version/evidence. No billing logic or unverified price assumptions in product.

Real adapter uses fixed reviewed Responses endpoint, pinned model and an expiring project-scoped operational approval file plus separate file-only API secret. Missing/expired/unverified configuration yields typed unavailable without sending context; no fake provider/alternate endpoint/fallback. Runtime approval is an operator attestation linked to actual account/contract review, not proof that this agent verified ZDR remotely. Static response schema carries no per-user enums or context. Context/plaintext keys/locks are released before inference; context is never persisted. Sensitive result/binding encrypt under per-user DEK; safe execution status/provider/model/prompt/timing/usage/failure metadata contain no report content. Retention is min(source Chronicle expiry, 30 days); users can remove commentary early. Scheduled cleanup and owner erasure include all AI inventory. Existing privileged full-suffix rollback/recovery residual remains; no independent AI freshness anchor is introduced.

Quota admissions persist in encrypted minimal request receipts with an authenticated technical dispatched timestamp; deleting an AI result never resets daily/minute limits or replays its original request. These receipts follow existing active-account command-audit purpose and contain no context/output. AI schema/provider availability is an optional capability, not a prerequisite of deterministic API readiness.
