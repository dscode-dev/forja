# Deterministic Reporting and Crônicas

## Report rule 1

Reporting composes owning-domain application reads and never writes financial/game state. One report covers one explicitly owned account and currency; no portfolio total/FX, category inference or AI. Account names, transaction descriptions and Identity information are excluded. Currency precision follows Finance. All values/context are S3; timezone/locale are frozen only inside encryption. Future Alquimista gets a minimized internal projection, not raw history or authority.

Identity timezone/profile revision is observed before acquiring the common owner guard; Work is observed likewise with its immutable revision. All Finance/Planning/Game reads then use the same guarded transaction. These earlier observations are explicit provenance, not a cross-store simultaneous snapshot.

DAILY uses one local civil date; WEEKLY is ISO Monday through Sunday containing that date; MONTHLY is its Gregorian month. CUSTOM has inclusive from/through, 1–366 civil days (Work's existing bound); no UTC-hour/day approximation. Resolve local start and day-after-through to exact UTC instants, start inclusive/end exclusive; a skipped civil midnight uses the first instant with that date and a completely skipped date yields an empty interval. Freeze UTC bounds/local labels/timezone/runtime tzdb version. Current periods are partial as of generation; future-only periods are rejected. Previous comparison uses prior day/week/calendar month, or the preceding equal number of custom civil days. Full previous periods are compared without normalizing a partial current period; flag this explicitly.

## Historical facts versus observed planning

Settled income/expenses/net include all accepted effective-time contributions in the interval at the captured Finance cursor, including signed reversals/replacements; opening/closure are not income. Opening balance is immediately before start, closing immediately before end (or generation for an unfinished period). Explicit baseline added during the period is separate: closing = opening + baselineChange + net. No account before its explicit opening has money. Later backdated adjustments restate newly generated reports; old snapshots retain their captured facts/cursor unchanged.

Use authenticated encrypted current account state, selected UTC contribution buckets and boundary events. Opening/closing derive by subtracting bounded post-boundary contribution buckets from current balance; exclude the original baseline before account opening. Authenticate bucket/checkpoint links and detect missing/stale selected buckets. Full UTC days use buckets, partial boundary days use effective-time events. At most 1,000 selected buckets/events/expectations/game awards across the request (including previous comparison/tail), plus fixed-size source reads. Excess yields BOUNDED_PERIOD_REQUIRED with no truncation or lifetime ledger decryption. Old periods with a long tail can require a later bounded maintenance/checkpoint capability; report retrieval itself reads its single frozen artifact. No async worker or separate analytics DB is implied.

Pending receivable/payable/predicted-income/scheduled-debit due within the report interval are a **generation-time planning observation**, not historical pending state at period end. Authenticate current item/audit and absence of settlement. Planned net = predicted + receivable − scheduled − payable; never add to settled metrics. Overdue items outside the interval are not silently included. Goal context is the current exclusively attributed non-cancelled goal/configuration/progress plus latest frozen required-income calculation if present, with all goal/calculation/Work/Finance references and stale flag. No historical goal configuration/progress is inferred; historical goal-change comparison is unavailable. No transfer/contribution ledger exists: report funding progress, not invented contribution transactions.

Reserve state is available only if an explicit active/completed RESERVE_TARGET mission still matches that dedicated goal’s funding/target/currency; savings type alone is insufficient. It is labeled declared-goal funding, not a household emergency-health threshold. Historical reserve movement is unavailable without a historical allocation baseline. Work capacity uses the observed immutable profile over the report's civil labels, explicitly labeled a declared scenario projected over those dates, not money earned or historical employment. Same-currency settled income minus known declared capacity is a mechanical comparison; unknown/mismatched currency remains null. Game XP gained/completions use recorded award timestamps within the report interval; current level/XP and award sequence are generation-time observations, separate from financial values.

Comparison absolute delta = current − previous. Percentage = delta × 100 / |previous|, rounded half away from zero to two decimal places (integer basis points, 100 basis points = 1%). Zero previous returns null with ZERO_BASELINE; no infinity or fabricated percent. Net negative baselines use absolute denominator and expose that convention. Exact BigInt for money/rational arithmetic; published values obey Finance bounds. No deterministic prose/advice is needed.

## Immutable artifacts and retention

An explicit random UUIDv4 generation command creates a Chronicle; same owner/key and normalized command returns the original artifact, conflicting reuse fails. Intentional regeneration uses a new key and owner generation sequence; prior artifacts are never rewritten. Snapshot freezes facts, planning/Work/Game observations and source versions; retrieval never recomputes from current sources. A separately encrypted immutable command receipt retains only normalized intent/fingerprint under existing active-account command-audit retention, preventing late replay after artifact expiry. Receipts contain no report metrics. Artifact retention is exactly seven days per security policy; expired content is inaccessible and bounded cleanup purges ciphertext on owner access. A late replay returns explicit expiry, never a silently regenerated snapshot. Full owner erasure removes artifacts and receipts before keys. A bounded minute-based backend sweep also purges dormant-owner expired artifacts without decryption; deployment must verify scheduling/lag/capacity, and cannot claim instantaneous physical deletion at TTL.

Opaque owner/request UUIDs, owner generation sequence, timestamps and key routing alone are S1 selectors. No plaintext period, account name, report metrics or sensitive hashes/indexes. Immutable request and artifact triggers permit only authorized erasure and, for artifacts, expired deletion. No independent Reporting freshness anchor; privileged complete valid suffix rollback remains a documented residual, as for Game/Work. Recovery/backup/key-migration inventories include both tables before deployment/key retirement.
