VS Code is the agent's primary environment; Unity Hub/Editor run natively on macOS. The physical **iPhone 15 Pro Max** is the authoritative mobile runtime validation device. Emulator/simulator/Editor results do not establish physical-device success. Follow [security](security.md#unitymobile-security-contract) for storage/secrets and [architecture](architecture.md#unity-architecture) for ownership.

The directly Hub-openable project is `apps/mobile` (Assets/Packages/ProjectSettings). Use the exact Editor/revision pinned in [development](development.md#pinned-tools) and ProjectSettings/ProjectVersion.txt. The selected Editor was opened by the developer and subsequently used for command-line compilation, tests and unsigned native build; see [executed evidence](prs/PR-01.md#native-command-line-validation--2026-10-04). Signed build, installation, launch and three relaunches passed on the physical device; the developer confirmed visual startup and three background/resume cycles. Performance measurement remains pending. `packages-lock.json` and normalized settings come from real Editor import. Review compatibility before changing the pin.

For Android, Unity → Settings/Preferences → External Tools → Android should use the SDK/NDK/JDK/Gradle installed with Unity. Avoid running Android Studio/emulators or external SDK adb commands concurrently if they restart a competing ADB server. Intel macOS Editor deprecation is a future support warning: Intel support continues through Unity 6.7 LTS. On Apple silicon, use the native Apple silicon Editor; on Intel, plan the workstation upgrade before adopting releases without Intel support. See [official Android tool settings](https://docs.unity.com/en-us/engine/6000.0/manual/platform-specific/android/getting-started/sdksetup/external-tools-reference) and [Intel support announcement](https://discussions.unity.com/t/unity-to-deprecate-intel-based-mac-support-starting-with-unity-6-6/1721740).

1. **Prerequisites:** macOS, Unity Hub login/license; install the pinned Editor from development.md using Hub (matching Mac architecture) with iOS Build Support. Install compatible Xcode/command-line tools for the iPhone's actual iOS version, complete first-launch components/license, and add your Apple ID under Xcode Settings → Accounts. Signing requires your real personal/developer team and a unique bundle ID you control; App Store distribution later requires Apple Developer program setup. Do not send passwords/certificates to the agent. [Unity's iOS setup](https://docs.unity3d.com/6000.6/Documentation/Manual/ios-environment-setup.html) describes the toolchain.
2. **Hub/Editor:** Hub → Projects → Add → Add project from disk → select the existing `apps/mobile` directory, without creating/moving a template project. Select the pinned Editor and open. Let package import finish. Confirm Console has no compilation/import errors. Open `Assets/Forja/Scenes/Bootstrap.unity`; check its bootstrap component has no missing script. Window → General → Test Runner → EditMode → Run All; export results. Enter Play Mode and confirm one `Forja bootstrap initialized.` message and neutral camera background; leave Play Mode.
3. **Unsigned generation:** File → Build Profiles → Add Build Profile → iOS → Switch Platform. Confirm Bootstrap is the sole enabled scene. Player Settings → Other Settings: IL2CPP, ARM64/device target, supported minimum iOS (check against installed Editor/device), no insecure HTTP, your unique controlled bundle ID. Keep signing credentials out of repository settings. Click Build into ignored `apps/mobile/Builds/iOS`; generating the Xcode project can be checked before device signing. No runtime PASS follows from generation alone.
4. **Connect/select physical device:** attach iPhone 15 Pro Max by USB-C, unlock and Trust This Computer; enable Settings → Privacy & Security → Developer Mode and restart/confirm if prompted. In Xcode Window → Devices and Simulators confirm the actual model/OS, pairing and developer support. Open generated Unity-iPhone.xcodeproj (or .xcworkspace if an actual dependency creates one). Select Unity-iPhone target → Signing & Capabilities → your real team and controlled bundle ID; allow automatic signing locally. Select scheme Unity-iPhone and the named **physical iPhone 15 Pro Max** as run destination, never a simulator/generic destination. Keep generated signing changes in ignored Builds.
5. **Build/run:** Xcode Product → Build, then Product → Run. Resolve provisioning/device-support issues with your own account. For diagnostics use a Development Build; do not enable deep profiling or collect sensitive memory. Launch on device, then background/resume and terminate/relaunch three times. No backend connection or game screens are expected in PR-01.
6. **Expected behavior/performance:** neutral full-screen camera background, successful bootstrap with no crash, missing scripts, repeated exception loop or unexpected network activity. Inspect responsiveness, stable orientation, resume behavior and Xcode CPU/memory trends over 60 seconds; report values/changes rather than claiming production performance from an empty scene. Bootstrap requests a 60 fps cap; verify observed frame timing rather than assuming it.
7. **Failure evidence:** sanitized Console/Editor.log (`~/Library/Logs/Unity/Editor.log`), Test Runner XML, first compiler/import error, Xcode build error and device crash/console logs, screenshot or recording of the symptom. Exclude credentials, token values, account data and device UDID; screenshots must contain only the empty bootstrap/configuration diagnostics.
8. **Return to agent:** exact Editor version/revision, package resolution/import result, macOS/Xcode versions, device model/iOS version, EditMode results, unsigned generation result, signed physical run result, observed CPU/memory/frame behavior, and sanitized failure evidence.
