## Runtime ownership and configuration

Core contains endpoint/environment validation, PKCE/callback validation, typed session values and exact minor-unit **formatting**. Application owns SessionCoordinator, sensitive view lifetime and the concrete API/browser/storage contracts. Infrastructure implements bounded HTTP/JSON and native iOS adapters. Presentation composes these dependencies and renders the read-only UI Toolkit shell using explicitly enabled built-in Input Manager (`activeInputHandler: 0`, no extra input package); scene callbacks only forward lifecycle events. [ADR 0016](adr/0016-native-ios-session-and-memory-only-shell.md) records the implementation choice. No financial command or calculation exists in mobile.

`Assets/Forja/Resources/ForjaEnvironment.asset` is the sole runtime configuration. Select it in the Inspector: environment development/production, API HTTPS **origin**, trusted OIDC issuer and public client ID, callback `com.darlan.forja.dev:/auth/callback`. The backend must be enrolled with exactly these public OIDC settings. No secret belongs here. Missing API config fails closed; absent provider settings are permitted only in development and disable login. Production requires provider configuration; future distribution identity remains unresolved. Configuration requires no source edit. The tracked asset has an intentionally empty endpoint/provider, not an example server. Never point a physical iPhone at the Mac's loopback endpoint; supply a reachable HTTPS origin with an OS-trusted certificate. No global ATS exception or certificate bypass exists.

Access and all private responses exist only in memory. The iOS native adapter implements the canonical [storage/lifecycle policy](security.md#unitymobile-security-contract); the only PlayerPrefs value is a non-sensitive installation marker. Keychain use on first installation purges the app refresh item before initializing that marker. ASWebAuthenticationSession uses ephemeral browsing and validates the exact state/path before completion. Editor and Android have no credential fallback: native session functionality fails closed there. EditMode tests use doubles only within the test assembly.

HTTP explicitly permits TLS 1.2 with default certificate/hostname validation (the pinned Unity managed API does not expose a TLS 1.3 flag; enabling it requires verified transport support), and uses no cookies/redirects/disk cache; each request has a 15-second deadline, cancellation, mandatory response no-store, 512-KiB body and JSON depth 32 limits. It never logs bodies/exceptions or introduces request IDs absent from backend contracts. Session renewal is serialized; the old refresh item is removed **before** network transmission and only the verified rotated response is saved. A process crash/lost response therefore requires fresh login instead of replaying a spent credential. Background/lock cancels ordinary work and clears memory, while the authentication sheet retains its transient PKCE context. Resume renews before fetching. Late responses cannot restore an old session view. Native privacy tracks the managed hide request separately from UIKit active/capture state, rechecks when UIKit becomes active, and removes the cover only after a safe UI frame is drawn. Configuration/error views participate in the same reveal lifecycle; capture-stop cannot override a pending managed privacy barrier. Logout clears local state even if remote revocation fails; the UI does not claim remote success. Revoke-all requires fresh server-verified authentication and tells the user to sign in again if denied.

The shell reads current identity, accounts, Work plus a seven-civil-day UTC capacity horizon pinned to the fetched Work revision, and goals plus settled progress. Accounts and goals display the first explicit page of at most 100 items and indicate further pages; no all-account total or globally atomic cross-module snapshot is implied. Missing Work or empty real lists show honest empty states. Estimates are labeled separately from received income. No domain mutation, final RPG assets or performance claim is introduced.

Build postprocessing registers only the callback scheme and links Security/AuthenticationServices; no new entitlement or global insecure network setting. Bundle ID remains `com.darlan.forja.dev`, signing stays local in ignored generated output. Android runtime/Keystore, release identity and distribution art/capabilities are later gates.

## Reproducible native checks

Use the pinned Editor with `-batchmode -nographics -projectPath <isolated-project> -runTests -testPlatform EditMode -testResults <local-xml> -logFile <local-log>`. To generate iOS, set `FORJA_IOS_OUTPUT` to ignored/temporary output and invoke `-batchmode -nographics -quit -buildTarget iOS -projectPath <isolated-project> -executeMethod Forja.Editor.ForjaIosBuild.Build -logFile <local-log>`. Then `xcodebuild -project <output>/Unity-iPhone.xcodeproj -scheme Unity-iPhone -configuration Debug -sdk iphoneos -destination 'generic/platform=iOS' -derivedDataPath <local-derived-data> CODE_SIGNING_ALLOWED=NO build`. These checks verify compilation/generation, never device behavior. Do not overwrite or terminate an open developer Editor; copy Assets/Packages/ProjectSettings/UserSettings to a local isolated project and preserve generated evidence privately. Package lock changes must come from actual Editor resolution.
